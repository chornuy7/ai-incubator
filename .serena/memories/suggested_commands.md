# Команды

## Разработка

| Команда | Что |
|---|---|
| `npm run sync` | **первый шаг любой задачи**: проверяет инструменты навигации, тянет `main` |
| `npm run dev` | фронт `:5173` + API `:3001` |
| `npm run dev:safe` | то же, API через `scripts/dev-api-safe.mjs` |
| `npm run dev:web` / `dev:api` | по отдельности |
| `npm run mcp:docs` | живая документация MCP |
| `npm run migrate` | `server/scripts/migrate.mjs` |

`npm run sync` **останавливается на грязном дереве** и печатает, что закоммитить. Это намеренно:
автостэш поверх чужой незакоммиченной работы в общем каталоге неразбираем.

## Проверка

`npm test` и `npx tsc --noEmit` — см. `mem:task_completion`, там же ловушка со списком тестов.

## Windows / PowerShell — отличия от unix-shell

Разработка идёт на Windows, оболочка по умолчанию — **Windows PowerShell 5.1**:

- **`&&` и `||` не работают** — синтаксическая ошибка. Последовательно: `A; if ($?) { B }`.
- Нет `head`/`tail`/`which`/`touch`/`wc`: `Get-Content -TotalCount N` / `-Tail N`,
  `(Get-Command x).Source`, `New-Item -ItemType File`, `Measure-Object -Line`.
- `2>$null` вместо `2>/dev/null`. Не перенаправлять stderr нативных exe: 5.1 оборачивает строки
  в ErrorRecord и рушит `$?` даже при коде выхода 0.
- `Set-Content`/`Add-Content` пишут в ANSI-кодировке — для файлов, которые читают другие
  инструменты, указывать `-Encoding utf8`.
- Пути с пробелами вызывать через `&`: `& "C:\Program Files\...\app.exe"`.

Git Bash тоже доступен и понимает обычный POSIX-синтаксис — но это отдельная оболочка, смешивать
синтаксис нельзя.

## Дев-сервер не запускать фоновым процессом

Поднимать только через preview-механизм агента. Фоновый bash оставляет висеть процесс, порт
занят, следующий запуск падает с невнятной ошибкой.
