# Фронт

React 18 + TypeScript + Vite, слои Feature-Sliced Design.

## Слои, снизу вверх

| Каталог | Что |
|---|---|
| `src/app/` | инициализация приложения, роутинг |
| `src/pages/` | экраны панели |
| `src/widgets/` | составные блоки экранов |
| `src/features/` | пользовательские сценарии |
| `src/shared/` | `ui/`, `lib/`, `config/`, `types.ts` — переиспользуемое |
| `src/api/` | клиент API, по файлу на домен (`accountsApi.ts`, `parserApi.ts`, …) |
| `src/mocks/` | моки |

Состояние — `zustand`, не Redux. Стили — Tailwind, классы через `clsx`.

## Ловушка: куда фронт ходит за данными

`api.config.json` в корне, поле **`useLiveApi`**:

- `true` — запросы `/api` уходят на **боевой** сервер;
- `false` — на локальный `node server/index.js`.

Читается в `vite.config.ts` на старте, Vite перезапускается сам. Файл **в `.gitignore`
намеренно**: случайно закоммиченный `"useLiveApi": true` увёл бы чужой дев на бой. Образец —
`api.config.example.json`; без файла всё работает на локальном бэкенде.

**Расхождение теста с ожиданием — сначала проверять этот флаг.** Половина «странных» отличий
объясняется тем, что панель смотрела на бой, а не на локальный сервер.

Настройка только для разработки: собранная панель всегда ходит на свой домен.

## Типы API

Типы ответов объявлены рядом с вызовами в `src/api/*.ts` (`export interface Account…`), а не в
общем `types.ts`. Общий `src/shared/types.ts` — для сквозных типов домена.
