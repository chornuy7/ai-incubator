# Что выполнить перед сдачей задачи

```
npm test
npx tsc --noEmit
```

Оба обязательны. Результат сообщается **числом** (сколько из скольких), не словом «прошло».

## Ловушка: тесты перечислены поимённо

`npm test` — **не глоб, а явный список ~140 файлов** в `scripts.test` внутри `package.json`.
Новый `server/__tests__/*.test.js` **не запустится никогда**, пока его туда не допишут — и
красный тест никто не увидит.

Завёл тест — добавь его в список тем же коммитом. Проверка полноты списка:

```
node -e "const p=require('./package.json'),fs=require('fs');const l=new Set(p.scripts.test.match(/server\/__tests__\/[\w.-]+\.test\.js/g)||[]);const m=fs.readdirSync('server/__tests__').filter(f=>f.endsWith('.test.js')).map(f=>'server/__tests__/'+f).filter(f=>!l.has(f));console.log(m.length?'НЕ ЗАПУСКАЮТСЯ:\n'+m.join('\n'):'список полон')"
```

## Если трогал `task.settings` или заводил модуль

Поле должно попасть в дескриптор MCP **тем же коммитом** — contract-тест
`server/__tests__/mcpDescriptors.test.js` сверяет схему с тем, что читает воркер. Подробности —
`mem:conventions`, раздел про MCP.

## Если правил воркеры или схемы

Бэкенд надо **перезапустить** — воркеры живут в памяти процесса, иначе увидишь старое поведение.
Что при этом происходит с активными задачами — `mem:server/core`.

## Линтера нет

`npm run lint` — это `tsc --noEmit`, тот же тайпчек. Отдельного шага форматирования/линта в
проекте не существует, искать его не надо.
