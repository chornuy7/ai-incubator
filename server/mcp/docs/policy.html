Murmex MCP — data use policy

Applies to the protected resource /api/v1/mcp · Referenced from protected resource metadata as resource_policy_uri (RFC 9728) · Version 1 — 27 August 2026

This page states what the Murmex MCP endpoint returns to a client, what a client may and may not do with it, and what obligations follow from the fact that this API performs real actions against real people on Telegram. It is written for whoever integrates an AI orchestrator against this server. "Client" below means any software holding an API key, including an autonomous agent.

1. What the resource returns

Three categories, with different obligations attached.

CategoryWhere it comes fromContains
Schema and catalogue
no personal data		 list_modules, describe_module, describe_block, list_capabilities (modules, services), resources/*, prompts/* Module descriptors, parameters, limits, presets, prices, platform subsystem descriptions.
Account holder data
personal data		 describe_capability(kind: "user"), list_capabilities(kind: "user"), GET /api/v1/capabilities/user[s] User id, display name, e-mail address, role names, permission map, balance and paid modules.
Operational data
may contain personal data		 get_task, create_task Task status and progress, the initiator, and the last 20 log lines. Log lines name the managed account that acted and state why an action was performed or skipped.

The endpoint does not return Telegram session strings, passwords, API keys, proxy credentials, or the message bodies of conversations. If any of those ever appear in a response, treat it as a security defect and report it (§8).

2. Purpose limitation

Data obtained from this resource may be used only to plan, validate, launch, monitor and report on work inside the Murmex account the key belongs to. Specifically:

  • Schema and catalogue data may be held for as long as it is useful, including in a model's context window and in a cache. It describes software, not people. Respect ttlMs if you cache it.
  • Account holder data may be used to decide what the key is permitted to do and to attribute work. It must not be used to build a profile of that person for any other purpose.
  • Operational data may be used to follow a run, diagnose it and report on it.

3. What a client must not do

Prohibited without exception.
  • Export account holder data (name, e-mail, roles, balance) to any third-party system, or disclose it to anyone other than the operator on whose behalf the client is acting.
  • Use data returned by this resource as training data for a model, or submit it to a third-party model provider for any purpose other than serving the operator's own request in the moment.
  • Combine data from this resource with external data sets to re-identify, enrich or profile message recipients.
  • Retain the API key anywhere it is readable by another tenant, another customer, or an end user.
  • Use the resource to reach people who have asked not to be contacted (§5).

4. Retention

  • Keep account holder data only for the lifetime of the session that needed it. Do not persist it to your own store as a matter of course.
  • Task logs may be persisted for operational history. They name managed accounts, so treat that store with the same care as the rest of the operator's data.
  • The server records that a call was made, by which key and to which tool, for audit. It does not record the content of generated messages in this endpoint's responses.

5. Data the client supplies, and the people behind it

This is the part that separates this API from an ordinary data endpoint. Several modules take a list of third parties who have not interacted with the operator and contact them:

neuro-commenting, neuro-chatting, mass-react, mass-looking, autopostingchannels, groupsPublic interaction under their posts or in their groups.
parsing-*channels, groupsTheir public profile is collected into a database.

The operator, not this platform, is the controller of that data. By supplying it you confirm that:

  • you have a lawful basis to process those people's data and to contact them, under the law that applies to them and to you;
  • you honour opt-outs. A person who asks not to be written to must be added to the platform blacklist, which is enforced before every action in every module, including by phone number in any notation;
  • you do not use the platform for content that is unlawful where the recipient is, and you accept that Telegram's own rules apply on top of this policy.
Automated decisions about people. neuro-dialogs classifies replies and moves a lead through a funnel automatically. If the people concerned are in a jurisdiction that grants rights over automated processing, those rights are the operator's to honour — this API gives you the lead record and the conversation, so you are able to.

6. Actions are real and irreversible

create_task is not a simulation. It publishes to Telegram from live accounts and debits the balance. Nothing it does can be undone — stop_task halts further actions but does not retract those already taken, and Telegram offers no rollback.

  • Call validate_task first and proceed only on valid: true.
  • Read the warnings: they mark fields you set that will be silently ignored.
  • An autonomous agent should have a human confirm the launch. The tool is annotated destructiveHint: true precisely so a client can gate it.

7. Credentials

The API key is a bearer credential: whoever holds it acts with the full permissions of its owner. Send it only in the Authorization header, never in a URL, and never in a page a third party can view. If it leaks, have it rotated in the server environment — it is not issued or revocable from the admin panel.

8. Reporting a problem

Report a suspected leak of personal data, an unexpected field in a response, or a compromised key to the platform operator through the support channel in the panel. If you believe the endpoint returned data it should not have, stop using the affected data and report it before doing anything else with it.

9. Status of this document

It states how this API expects its data to be handled; it is not legal advice and it does not replace the operator's own privacy notice, processing agreements or terms of service.
