## 1. ЦЕНЫ — рефактор `(Highest, Николай)`

**Проблема:** цена действия считается по формуле `база + текст_по_максимуму` (напр. `0.05 + 1.024
= 1.074`). Это **неправильно** — расчёт «за символы/токены» ИИ придумал сам. И цены **захардкожены
в коде** (`pricing.js`, `tokenLedger.js`, `modules.ts`), хотя должны браться только из БД.

**Правило цены (заказчик, ещё с созвона 2+ назад):**
- Цена для юзера = `база_за_действие (из БД) × N_действий`. **Всё.** Математика простая.
- База (напр. `0.05 ⚡`) **уже включает** текст (с картинкой и без), картинку, нашу маржу, все
  расходы. Отдельного расчёта за символы/токены **быть не должно**.
- Пользователю цена за токен/символ и себестоимость **не показываются** — он всегда видит цену
  за действие.

**Задачи:**
- **Убрать из кода все статичные значения цен.** `pricing.js`: удалить `MODULE_MONTH_PRICE`,
  `COINS_PER_1K_TOKENS`, `maxTextTokens/maxTextCoins/fullActionPrice`-логику текста, `estimateCost`
  (не используется), мусорный `subscriptionCost`. `tokenLedger.js`: файловое хранение расходов
  убрать (только БД). Ни в одном файле не должно быть статичных цен.
- Все ценовые значения — **только из БД**. Нет в БД → **спросить, надо ли добавлять** (не добавлять
  автоматом мусор вроде «цена за 1000 токенов», которого вообще не должно существовать).
- Показ в панели: любое вычисление расхода во всех модулях/парсингах = `цена_за_действие × N`.

**Доп. (совет Андрея, отдельной задачей):** в админке «Цены» показывать рядом **себестоимость**
и **цену для юзера** (видеть маржу) + столбец **токенов/мес по подписке**.

## 2. АККАУНТЫ — подписки, доступы, роли `(Highest)`

**Архитектура подписок — «огромная дырка»:**
- `subscriptions.modules` хранится **JSON-массивом** → нужна нормальная таблица
  `user_subscriptions` (user_id ↔ модуль/подписка + **дата истечения `due`**). Сейчас срок
  действия подписки **нигде не хранится** — система не знает, когда подписка кончилась.
- **Баг:** любая покупка трактуется как **подписка**, а не докупка модуля → купил модуль →
  подписка «обновилась», ранее открытые модули **исчезли**.
- **Баг:** уже оплаченный модуль можно выделить и «оплатить» повторно — должен быть заблокирован.

**Роли и доступы:**
- Роль выбирается **дропдауном (одна роль)**, а не «кашей» из списка всех ролей.
- Владелец управляет **доступами** субов (настройки по доступам, не «ролевые игры»); управление
  ролями тоже здесь.
- Подписки: **добавлять/убирать модули** в подписку (как доступы).

**Уже починено на этом созвоне (подтверждено):** роль админа при покупке тарифа не назначалась
(теперь назначается); в «Пользователях» светились все юзеры платформы (теперь только свои субы +

## 4. УСТАЛОСТЬ `(Highest, Илья)`

- Отдых и восстановление **объединены — это неправильно**, вернуть раздельно:
  **порог усталости = порог действий** (сколько подряд), **отдых** отдельно, **восстановление**
  отдельно.
- **Баг шанса по часам / распорядок дня:** в 11:00 у аккаунта 89 % согласия, но «не попал» —
  логика рандома (число 0..1 vs порог) похоже **инвертирована**, перепроверить.

**Будущая модель (обсудили, делаем ПОЗЖЕ, не сейчас):** задержка между действиями + скорость
печати per-аккаунт (рандом 80–140 зн/мин + погрешность/рандомайзер), один аккаунт в нескольких
модулях одновременно → учёт кросс-модульной усталости и **физической невозможности** (нельзя
комментировать и писать в ЛС в одну секунду), разные «пути» между действиями (коммент→ЛС ≈ 3 с,
ЛС→реакция ≈ 0.5 с), «личность/распорядок дня». Сейчас — только вернуть раздельность и порог=действий.
