## 2. Тестирование функционала — задача недели `(Highest, Илья)`

Заказчик: слишком долго откладывали запуск. Нужно **пошагово** проверить каждый обязательный
блок задачи (защита, промпты, тайминги) и убедиться, что «ИИ не пересчитывает ни вправо, ни
влево» и всё происходит как задумано. На этой неделе — **первый полноценный тест**, не «100
аккаунтов разбежались кто куда».

**Детальный тест таймингов и усталости** (эталонный сценарий с созвона):
- аккаунт (напр. Trader Diares) → распорядок: **везде 0–1 % шанс, кроме одного часа (100 %)**;
- задержки близкие и **разведённые с усталостью**: напр. задержка 5 мин, а отдых после
  переутомления — 7 мин (число, не кратное 5), порог усталости 15, восстановление за час;
- **2 действия** всего;
- проверить: **счётчик усталости растёт только на СОВЕРШЁННОМ действии, не на попытке**;
- в логах видно попытки «0 % → не сработало»;
- 2-е действие не проходит через 5 мин (аккаунт ещё отдыхает), проходит только на 10-й минуте;
- по завершении 2-го действия задача уходит в «Готово».

**Отдельно:** отключение защиты аккаунта — если защита выключена, движок игнорирует её
полностью; включена — следует всем настройкам внутри.

## 3. Безопасность БД — RLS-политики `(Highest, Николай)`

**Критично.** В Supabase → Policies **пусто на всех таблицах**: бэкенд доступ не проверяет
(проверка только на фронте). Нужна миграция с политиками **на каждую таблицу, используемую
авторизованным пользователем**:

```
for all to authenticated
using ( exists (select 1 from public.profiles p
        where p.id = auth.uid() and p.active = true) )
```

То есть доступ к данным только у пользователя, чей `profiles.active = true`. Проверить, что
при `active = false` любой запрос к защищённым таблицам отдаёт отказ.

## 6. Баг таймингов — сброс в Custom `(High, Николай)`

При изменении любого значения панель **сразу прыгает в Custom**, а Custom получает пресет по
умолчанию. Правильно:
- **Custom не должен быть предустановленным** пресетом;
- при переключении/правке значения должны **наследоваться от пресета, с которого перешли**
  (Консервативный → правка → Custom с значениями Консервативного, а не сброс);
- сам факт переключения на пресет **не должен сбрасывать в Custom**.

Доработка `src/features/modules/shared/TimingSection.tsx`.

## 7. Оптимизация запросов `(High, Илья частично + знать обоим)`
