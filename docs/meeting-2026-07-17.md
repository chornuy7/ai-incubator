# Роадмап по созвону 17.07.2026 (демо + правки)

> Источник: запись созвона `2026-07-17 18-05-50.srt` (кросс-тест Ильи и Николая + заказчик).
> Формат: замечание → почему → где в коде (по индекс-карте) → статус.
> Статусы: `☐` не начато · `◐` в работе · `☑` готово (этой сессией/Николаем) · `🧠` требует архитектурного решения.

## 0. ГЛАВНОЕ: архитектура оркестрации (🧠 «залезть в мозги клоду»)

Заказчик прямым текстом: *«цели → компании → задачи, прям как уровни; автоматизация под компанию или под задачу; нельзя запустить задачу к цели напрямую»*. Текущая имплементация «кривая, одно ломает другое». Фиксируем целевую модель — на неё завязано ~половина правок ниже.

```
ЦЕЛЬ (солнце)        — стратегия: что и к какому сроку. Оркестрирует кампании.
  └─ КАМПАНИЯ (небо)  — исполнение под целью: закреплённые аккаунты + НАСТРОЕННЫЙ модуль (пресет).
       └─ ЗАДАЧА (земля) — один запуск модуля под кампанией. Ручные задачи — тоже сюда.
            └─ МОДУЛЬ  — инструмент. Настраивается пресетом.
  АВТОМАТИЗАЦИЯ        — планировщик. Крепится к КАМПАНИИ или к ЗАДАЧЕ. Не к «голому» модулю.
```

**Правила модели:**
1. Задачу **нельзя** запустить «к цели» напрямую — только через кампанию (сейчас в модуле есть «выбор цели» — заменить на «выбор кампании»).
2. Кампания **обязана настраивать модуль** (через пресет), а не только выбирать аккаунты. Сейчас кампания только аккаунты берёт — «нафиг нужна неконтролируемая кампания».
3. Автоматизация **не существует сама по себе**: только под настроенную кампанию или под задачу (внутри модуля). Нельзя автоматизировать ненастроенный модуль.
4. AI-промты/этапы/база знаний — берутся из **ЦЕЛИ** (кампания их наследует).
5. Аккаунт «плавает» в общем пуле ИЛИ закреплён за кампанией (не за «ролью»). Закрепление = замочек + имя кампании.

**Файлы модели:** `server/goals.js`, `server/lib/campaign.js`, `server/campaignsRoutes.js`, `server/campaignSchedules.js`, `server/modules/registry.js`, `server/modules/workers.js`, `server/automation/*`, `server/leads.js`; фронт — `GoalsPage.tsx`, `CampaignPage.tsx`, `AutomationPage.tsx`, `TasksPage.tsx`, `LiveModule.tsx`, `AccountsPage.tsx`.

## 1. Резервация «роль» → «кампания» + замочек (🧠 ядро модели)

- ☑ Уже сделано ранее: аккаунт на паузе показывает модуль/«вручную».
- ☐ В менеджере колонку **«Роль» переименовать в «Кампания»** — под какой кампанией работает аккаунт. Везде убрать понятие «роль как группа» (`AccountsPage.tsx`, `accountsMeta.js` — поле `role` → `campaignId`/`campaign`).
- ☐ **Замочек** рядом с именем кампании: закреплён за целью/кампанией (лочен) → замок + имя; плавает в общем пуле → без замка (`AccountsPage.tsx`).
- ☐ Присвоение аккаунта кампании: «присвоить (лок)» или «использовать (без лока)».
- ☐ При смене кампании одному аккаунту — **дропдаун** (выбор существующей / создать свою), не bulk-переезд ломающий роль (`AccountsPage.tsx` bulkMove).

## 2. Менеджер аккаунтов (Lane A)

- ☑ Меню статусов (активные/в работе/прогрев) + скрытые кнопки запуск/пауза/стоп (Николай).
- ☐ **Чекбокс-заголовок 3 состояния**: unchecked / **indeterminate (semi-checked)** / checked. Клик по semi → снять всё. Убрать кнопку «Снять» (`AccountsPage.tsx`).
- ☐ «**В корзину**» перенести туда, где была «Снять» (крайняя справа) — самая редкая деструктивная функция.
- ☐ Кнопка «**Управление**» (открыть мульти-просмотр выбранных аккаунтов).
- ☐ **Запрет удаления аккаунтов «в работе»** — сначала стоп. Сейчас баг: активный уходит в корзину, статус не меняется (`AccountsPage.tsx` bulkTrash + сервер lock-guard).
- ☐ Корзина: «**Восстановить выбранные**» (сейчас восстановление криво/для одного). Восстановление возвращает «в работе» назад.
- ☐ Фильтр в корзине: показать ещё «живые» среди удалённых (валидность).
- ☐ **Score аккаунта** виден + где можно/нельзя использовать (напр. низкий траст → нельзя в mailing — писать это в статистике аккаунта). Score обновляет статус (`accountStats.js`, `trustScore.js`, `AccountManagementModal.tsx`).

## 3. Обзор аккаунта = вьюшка (не модалка), как почта/WhatsApp (Lane A/B)

- ☐ Открывать управление аккаунтом **панелью/страницей**, не модалкой поверх (перегруз).
- ☐ Слева — **колонка-список аккаунтов** (с фильтром), справа — табы (профиль/прокси/каналы/статус/действия).
- ☐ **Таб сохраняется** при переключении аккаунтов (централизованное состояние табов) + чекбокс «сбрасывать на профиль».
- ☐ Мульти-просмотр (выбрал N → «Управление»): раскладка как почта — список слева, детали+табы справа.
- ☐ Каналы/чаты **не стакаются** между аккаунтами — у каждого только свои (сейчас суммируются — баг) (`accountStats.js`, `AccountManagementModal.tsx`).
- ☐ **Превью картинок/видео**: не хранить оригинал; тянуть из Telegram по запросу и показывать, либо хранить ужатую копию ≤5 КБ (100×200, урезанная палитра). Возможно — только ссылки/подгрузка on-demand из сессии (`neuroDialogs/*`, `accountStats.js`).
- ☐ Переключение диалогов/групп **внутри блока**, не снаружи; список с фильтром; убрать стакинг.

## 4. Цели (🧠 + Lane B)

- ☑ Каналы/группы цели через FolderPicker (эта сессия).
- ☐ **Дедлайн цели** (опционально, но выбор обязателен): по истечении — цель «сгорает»/помечается завершённой/незавершённой и **останавливает работу** (`goals.js` + `GoalsPage.tsx`).
- ☐ **Цель по лидам** (сколько лидов привести) — опционально/обязательно тумблером.
- ☐ **Время выполнения** цели (опционально).
- ☐ **База знаний с файлами** (не только текст) (`goals.js` KB + `GoalsPage`).
- ☐ Создание/редактирование цели — **полноэкранная вьюшка**, не модалка.
- ☐ **Список кампаний** внутри/под целью (цель оркестрирует кампании).

## 5. Кампании (🧠 ядро — «сырое, переделать»)

- ☐ **Список кампаний** + кнопка «Создать кампанию» → **вьюшка** «Новая кампания» + «Назад» (не модалка) (`CampaignPage.tsx`).
- ☐ Кампания принадлежит цели; **обязательно настраивает модуль** (пресет), не только аккаунты.
- ☐ **Выбор аккаунтов — 3 режима:**
  1. **Числовой** — «взять N из общего пула» (скролл-число).
  2. **Ручной** — список свободных (незакреплённых) аккаунтов с фильтрами (страна и т.д.) → закрепляются за кампанией.
  3. **Папка** — выбрать папку → аккаунты закрепляются за кампанией+целью.
- ☐ Закреплённые аккаунты **выходят из общего пула** (лок за кампанией). Аккаунты могут «гулять» между целями/кампаниями только если НЕ закреплены (`campaign.js`, `accountLocks.js`, `accountsMeta.js`).

- ☐ Автоматизация крепится **к кампании или к задаче**, не к «голому» модулю.

## 7. Модули — порядок и запуск (Lane B)

- ☐ **Тайминги / настройки комментирования — вниз** (меняются редко).
- ☐ Убрать блок «**История сообщений**».

- ☐ **Пресеты модуля**: настройка + выбор пресета (быстрый конфиг), **цветовая метка**, персональные (Маша/Паша). Пресет = быстрый запуск; автоматизация = расписание (`modulesApi.ts` presets, `LiveModule.tsx`).

- ☐ **Проверка уникальности задачи перед запуском** (не «сканирование», а проверка): не создавать вторую идентичную задачу (те же аккаунты/цель/кампания/пресет) (`registry.js` validateSettings / `taskStore.js`).
