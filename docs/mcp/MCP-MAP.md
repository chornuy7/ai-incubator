# MCP — живая карта

Реестр того, что MCP обязан описывать, и текущее покрытие. **Обновляется в том же коммите,
что и код.** Каждое утверждение ниже подтверждено файлом — если ссылка не сходится с кодом,
это баг карты, чините карту.

Дата среза: **14.08.2026**. Формат описания — [MCP-SPEC.md](./MCP-SPEC.md).

> **Покрытие полное: 15 модулей из 15 (14.08).** Этапы 1–3 закрыты. Карта ниже переехала в исполняемый дескриптор
> [`server/mcp/descriptors/neuro-commenting.js`](../../server/mcp/descriptors/neuro-commenting.js)
> и проверяется contract-тестом. Доступ:
> - **MCP-протокол** — `POST /api/v1/mcp` (JSON-RPC 2.0, Bearer-ключ), инструмент `describe_module`;
> - глазами через REST — `GET /api/v1/modules/neuro-commenting/describe`;
> - покрытие модулей — `GET /api/v1/modules`.

## 2. Нейрокомментинг — полная карта

### 2.1. `whoAmI`

| Поле | Значение |
|---|---|
| **summary** | Пишет ИИ-комментарии под постами публичных каналов от имени управляемых Telegram-аккаунтов. |
| **does** | подписывается на канал и его группу обсуждения → выбирает пост по правилу режима → генерирует текст моделью (с учётом цели, базы знаний и агента) → публикует комментарий → пишет результат в логи и историю задачи |
| **doesNot** | не пишет в личные сообщения (это «Мейлинг»/«Нейродиалоги») · не постит в свои каналы (это «Автопостинг») · не ставит реакции (это «Массовые реакции») |
| **requires** | ≥1 аккаунт в статусе, допускающем работу, с рабочим прокси · ≥1 канал-цель · рабочий `OPENAI_API_KEY` |
| **risks** | Реальные публикации в Telegram. Неверные тайминги → FloodWait → карантин → спамблок. При недоступном ИИ задача **останавливается целиком**, а не льёт шаблоны ([workers.js](../../server/modules/workers.js), `mode === 'fatal'`). |
| **costModel** | Списание за действие по прайсу модуля; генерация текста включена в цену действия (MR-149). Анализ картинок биллится отдельно с множителем `imageMultiplier` и **только после успешной отправки**. |

### 2.2. Блоки

| id | Заголовок | Что делает | API и что заполняет |
|---|---|---|---|
| `accounts` | Выберите аккаунты | Какими аккаунтами выполняется задача; занятый другой задачей аккаунт не выдаётся (1 аккаунт = 1 задача) | `POST /api/modules/neuro-commenting/tasks` → `accountIds` |
| `targets` | Каналы | Куда комментируем и какую глубину истории смотрим | → `channels`, `postWindow` |
| `modes` | Режимы | Как выбирается пост и чем ограничена задача — количеством или временем | → `commentMode`, `workMode`, `postFilter` |
| `filters` | Фильтры постов | Отсев постов до генерации: слова, объём, вероятность, смысловая близость к цели | → `keywords`, `stopWords`, `minWords`, `probability`, `semanticFilter`, `semanticThreshold` |
| `limits` | Лимиты | Сколько всего и сколько на аккаунт; при работе по времени — длительность | → `maxComments`, `minComments`, `maxPerAccount`, `minPerAccount`, `durationMinutes` |
| `prompts` | Промпты и генерация | Каким тоном и по какому шаблону пишется комментарий | → `promptIndex`, `promptText`, `promptOverrides`, `typeWeights`, `analyzeImages` |
| `protection` | Защита аккаунтов | Множитель задержек и потолок вероятности действий | → `aiProtection`, `protectionLevel` |
| `timings` | Тайминги и задержки | Паузы между действиями и реакция на FloodWait | → `delayPreset`, `delays.*` |
| `binding` | Привязка | К какой цели/кампании/агенту относится задача и когда она прекращается | → `goalId`, `campaignId`, `agentId`, `deadline` |

### 2.3. Параметры (33 поля, 30 верхнеуровневых ключей)

Легенда: **тип** · **деф.** — значение по умолчанию · **огр.** — ограничения.

#### Блок `accounts`

| Параметр | Тип | Деф. | Огр. | Что делает |
|---|---|---|---|---|
| `accountIds` | `string[]` | — | **обязателен**, ≥1 элемент | ID аккаунтов, которыми работает задача. Пустой массив → отказ «Выберите хотя бы один аккаунт» ([registry.js](../../server/modules/registry.js) `validateSettings`). Аккаунты перебираются по кругу; недоступные по статусу/распорядку/лимиту пропускаются. |

#### Блок `targets`

| Параметр | Тип | Деф. | Огр. | Что делает |
|---|---|---|---|---|
| `channels` | `string[]` | — | **обязателен**, ≥1 | Каналы-цели: `@username` или `https://t.me/…`. Синоним `targets` — сервер принимает оба (`settings.targets \|\| settings.channels`). Канал выбирается случайно на каждой итерации. |
| `postWindow` | `integer` | `20` | 1…50 (жёстко клампится) | Сколько последних постов канала рассматривать. Не «вся история» — окно. |

#### Блок `modes`

| Параметр | Тип | Деф. | Значения | Что делает |
|---|---|---|---|---|
| `commentMode` | `integer` | `0` | `0` Случайный · `1` По ключевым словам · `2` Все посты | `0` — из отфильтрованных кандидатов берётся **один случайный**. `1` — остаются только посты, содержащие хотя бы одно из `keywords`. `2` — комментируются все кандидаты окна. ([workerLoop.js](../../server/lib/workerLoop.js) `pickCommentCandidates`) |
| `workMode` | `integer` | `0` | `0` По количеству · `1` По времени | `0` — задача идёт до достижения лимита действий. `1` — до истечения `durationMinutes`; **если `durationMinutes` не задан при `workMode=1`, задача не завершится по лимиту** ([accountRunner.js](../../server/lib/accountRunner.js) `totalLimitReached`). |
| `postFilter` | `integer` | `0` | `0` Только новые · `1` Только существующие · `2` Все посты | `0` — остаётся **только самый свежий** пост окна. `1` — все, **кроме** самого свежего. `2` — фильтр не применяется. |

#### Блок `filters`

| Параметр | Тип | Деф. | Огр. | Что делает |
|---|---|---|---|---|
| `keywords` | `string[]` | `[]` | — | Ключевые слова. Работают **только при `commentMode = 1`**; сравнение по вхождению подстроки, регистр не важен. Пустой список = фильтр не режет ничего. |
| `stopWords` | `string[]` | `[]` | — | Стоп-слова: пост, содержащий любое из них, исключается **всегда**, независимо от режима. Инструмент тональности («нежелательные темы»). |
| `minWords` | `integer` | `0` | ≥ 0 | Минимум слов в посте, чтобы его вообще рассматривать. `0` = выключено. |
| `probability` | `integer` | `30` | 0…100, `%` | Вероятность, что подходящий пост будет прокомментирован. **Внимание:** при `aiProtection = true` потолок урезается уровнем защиты — Консервативный ≤25 %, Сбалансированный ≤45 %, Агрессивный без ограничения ([protection.js](../../server/lib/protection.js) `effectiveProbability`). Заданные 80 % на консервативной защите превратятся в 25 %. |
| `semanticFilter` | `boolean` | `false` | требует `goalId` | Считает векторную близость поста к тексту цели и отбрасывает далёкие. Без выбранной цели и без доступных embeddings молча выключается (пишет warning в лог). |
| `semanticThreshold` | `number` | `0.2` | 0…1 | Порог косинусной близости. Ниже порога — пост пропускается. Проверено на живых данных: релевантный пост ≈0.52, офтоп ≈0.09. |

#### Блок `limits`

| Параметр | Тип | Деф. | Огр. | Что делает |
|---|---|---|---|---|
| `maxComments` | `integer` | `100` | ≥ `minComments` | Максимум комментариев за задачу. Синоним `maxActions` — сервер читает `maxActions ?? maxComments ?? 100` ([targets.js](../../server/lib/targets.js)). |
| `minComments` | `integer` | `0` | ≤ `maxComments` | Нижняя граница. **Фактическая цель задачи — случайное число из `[min, max]`**, детерминированное по ID задачи (`seededTarget`): две задачи с одинаковыми настройками получат разные цели — так поведение не выглядит машинным. Прогресс считается к этой цели, а не к максимуму. |
| `maxPerAccount` | `integer` | `0` | ≥ `minPerAccount` | Потолок действий на один аккаунт. `0` = без ограничения на аккаунт. |
| `minPerAccount` | `integer` | `0` | ≤ `maxPerAccount` | Нижняя граница цели на аккаунт (та же логика `seededTarget`). |
| `durationMinutes` | `integer` | `60` | > 0 | Длительность при `workMode = 1`; игнорируется при `workMode = 0`. **Трактуется как МАКСИМУМ**: фактическая длительность — случайное число из `[min, durationMinutes]`, где `min` задаёт уровень защиты — консервативный 60, сбалансированный 45, агрессивный 30 минут ([workModeDuration.js](../../server/lib/workModeDuration.js) `MIN_BY_PROTECTION_LEVEL`). |

> Нарушение `min > max` по парам `minActions/maxActions`, `minComments/maxComments`,
> `minPerAccount/maxPerAccount` — запуск отклоняется с текстом «Минимум больше максимума».

#### Блок `prompts`

| Параметр | Тип | Деф. | Огр. | Что делает |
|---|---|---|---|---|
| `promptIndex` | `integer` | `0` | 0…5 | Выбор карточки промпта: `0` Позитивный комментарий · `1` Интимный · `2` Эмоциональный отклик · `3` Вопрос автору · `4` Краткий отзыв · `5` Аналитический подход. |
| `promptText` | `string` | `''` | — | Свой системный промпт. **Имеет наивысший приоритет** — заданный непустой текст перекрывает и `promptIndex`, и `promptOverrides` ([commentGenerator.js](../../server/neuroCommenting/commentGenerator.js) `resolveSystemPrompt`). |
| `promptOverrides` | `string[]` | `[]` | по индексам карточек | Переопределение текста конкретных карточек, не ломая выбор по индексу. |
| `typeWeights` | `number[]` | `[]` | сумма нормируется | Распределение типов комментариев в процентах. **Если задан хотя бы один вес > 0, `promptIndex` не используется** — тип выбирается взвешенным жребием на каждый комментарий. |
| `analyzeImages` | `boolean` | `false` | — | Описывать фото поста моделью и комментировать по сути изображения, а не по «[медиа]». Биллится с множителем `imageMultiplier` (админка) и **только после успешной отправки** комментария. На семантический фильтр не влияет — тот считается по исходному тексту. |

#### Блок `protection`

| Параметр | Тип | Деф. | Значения | Что делает |
|---|---|---|---|---|
| `aiProtection` | `boolean` | `true` | — | Включает потолок вероятности из `protectionLevel`. Выключен — `probability` берётся как есть. |
| `protectionLevel` | `integer` | `1` | `0` Консервативный · `1` Сбалансированный · `2` Агрессивный | Множитель задержек ×1.8 / ×1 / ×0.75 и потолок вероятности ≤25 % / ≤45 % / без ограничения. |

> ⚠️ **Ловушка для «мозгов».** Порядок значений у `protectionLevel` и `delayPreset`
> **противоположный**: `protectionLevel = 0` — Консервативный (самый безопасный),
> а `delayPreset = 0` — Агрессивный (самый быстрый). Это не опечатка карты, так в коде.

#### Блок `timings`

| Параметр | Тип | Деф. | Огр. | Что делает |
|---|---|---|---|---|
| `delayPreset` | `integer` | `1` | `0` Агрессивный ×0.6 · `1` Сбалансированный ×1 · `2` Консервативный ×1.8 · `3` Custom ×1 | Масштабирует все задержки. Итоговый множитель = `LEVEL_MUL[protectionLevel] × PRESET_MUL[delayPreset] × глобальный`. Поля задержек редактируются **только** при `delayPreset = 3` (Custom) — на пресетах значения зафиксированы. |
| `delays.comment` | `[number, number]` | `[30, 120]` | сек, пол 5 с | Пауза между комментариями. Реальная пауза — случайная из диапазона × множитель, но не меньше 5 с. |
| `delays.join` | `[number, number]` | `[84, 156]` | сек, **пол 60 с** | Пауза перед вступлением в канал/группу обсуждения. Ускорить пресетом нельзя: Telegram считает вступления жёстче остальных действий, и множители агрессивных настроек срезали 90–240 с до 32 с → FloodWait и карантин ([protection.js](../../server/lib/protection.js) `MIN_JOIN_DELAY_SEC`). |
| `delays.floodWait` | `number` | `120` | сек | Запас поверх длительности FloodWait, которую вернул Telegram. |
| `delays.floodQuarantine` | `integer` | `3` | ≥ 1 | Сколько FloodWait подряд до отправки аккаунта в карантин. |

### 2.4. Расшифровка пресетов

**`delayPreset` — темп** (источник: `PRESET_MUL` в [protection.js](../../server/lib/protection.js), UI обязан совпадать):

| Значение | Название | ×пауз | ×длительности | Что физически делает | Когда брать |
|---|---|---|---|---|---|
| 0 | Агрессивный | 0.6 | 0.75 | Паузы реже вдвое → больше действий в час, выше шанс FloodWait и ограничений | прогретые «расходные» аккаунты |
| 1 | Сбалансированный | 1 | 1 | Базовые задержки | повседневная работа |
| 2 | Консервативный | 1.8 | 1.5 | Паузы почти вдвое длиннее → минимум риска бана | новые и дорогие аккаунты |
| 3 | Custom | 1 | 1 | Задержки берутся как введены, без масштабирования; только здесь поля разблокированы | ручная тонкая настройка |

**`protectionLevel` — защита** (источник: `LEVEL_MUL` + `effectiveProbability`):

| Значение | Название | ×задержек | Потолок вероятности | Что физически делает |
|---|---|---|---|---|
| 0 | Консервативный | 1.8 | ≤ 25 % | Действует максимум по четверти подходящих постов, паузы максимальные |
| 1 | Сбалансированный | 1 | ≤ 45 % | Действует не более чем по половине целей |
| 2 | Агрессивный | 0.75 | без ограничения | Работает по всем подходящим целям, паузы короче базовых |

### 2.5. Общие правила поведения (не параметры, но «мозгам» знать обязательно)

- **Один аккаунт = одна задача.** Занятый аккаунт другой задачей не выдаётся.
- **Пропуск по статусу.** `quarantine`, `spamblock`, `invalid`, `frozen`, `reauth` — аккаунт
  пропускается молча (с записью в лог), задача не падает.
- **Суточные лимиты §6** считаются **у аккаунта, а не у задачи** и общие для всех модулей:
  профиль, отработавший смену в другом модуле, сюда уже не попадёт.
- **Полный круг пропусков** (все аккаунты недоступны) → задача корректно завершается с
  указанием причины, а не крутится вхолостую.
- **ИИ недоступен → задача останавливается.** Шаблонные отписки от живых аккаунтов в реальные
  каналы не публикуются.
- **Дубли исключены**: пара «аккаунт + канал + пост» комментируется один раз (`actionKeys`);
  последние 50 отправленных текстов запоминаются, чтобы разные аккаунты не написали одно и то же.

### 2.6. Находки при составлении карты (в работу)

| Находка | Суть | Что делать |
|---|---|---|
| **`aiMode` — мёртвое поле** | Есть в TS-типах (`NeuroCommentingSettings`, `modulesApi`), сервером **не читается нигде** | Удалить из типов или реализовать. В дескриптор **не включать**. |
| **Двойное имя лимита** | `maxActions` и `maxComments` — одно и то же, сервер читает оба | В дескрипторе — одно каноническое имя + `alias`; в MCP отдавать канон |
| **Инверсия шкал** | `protectionLevel` и `delayPreset` нумеруются в противоположном порядке | Задокументировано (§2.3); в дескрипторе — явный `means` у каждого значения |
| **`durationMinutes` без страховки** | `workMode = 1` без `durationMinutes` = задача без условия завершения | Сделать `durationMinutes` обязательным при `workMode = 1` на уровне схемы |
