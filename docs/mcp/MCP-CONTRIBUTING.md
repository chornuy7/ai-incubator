# MCP — правила для команды

Короткий файл. Читать целиком, он весь про одно правило.

---

## Кто что делает

- **MCP пишем мы (Илья / Lane A).** Сервер, дескрипторы, транспорт, инструменты — наша зона.
  Николай MCP **не разрабатывает** и не обязан в нём разбираться.
- **Но регистрировать поля обязаны все.** Любое новое поле, любой новый модуль, любое
  изменение ограничения — попадает в дескриптор в **том же коммите**, что и код.

## Почему это не бюрократия

Заказчик встал именно на этом: манифест обещал «мозгам» 5 полей, а модуль принимал 30 с
лишним. Оркестратор, написанный по такому описанию, собирает задачи, которые не работают.

> «Ни хрена не соотносятся то, что написано в джейсоне, с тем, какие параметры реально есть
> у каждого модуля… конкретно сейчас MCP-шка — это то, что держит меня дальше с производством
> мозгов».

Пока MCP не описывает реальность, «мозги» не пишутся. Одно незарегистрированное поле снова
делает описание враньём — и стоимость этого несёт весь проект, а не автор поля.

## Правило

> **Добавил или изменил поле, которое сохраняется в задачу → внеси его в дескриптор модуля
> в том же коммите.**

UI-only поля (поиск по списку, сортировка, фильтры отображения) регистрировать **не нужно** —
только то, что улетает в `task.settings` и в БД.

## Как это делается (5 минут)

1. Открой `server/mcp/descriptors/<ключ-модуля>.js`.
2. Добавь элемент в `params`. Минимально обязательные поля:

```js
{
  name: 'postWindow',        // ровно как в settings
  block: 'targets',          // id существующего блока
  title: 'Окно постов',      // как называется для человека
  type: 'integer',
  default: 20,
  min: 1, max: 50,           // ограничения — если они есть, они ОБЯЗАТЕЛЬНЫ
  purpose: 'Сколько последних постов канала рассматривать.',  // зачем поле нужно
}
```

3. Если у поля есть варианты значений — расписать **что каждый вариант делает**, а не только
   как называется. Не «`0` / `1` / `2`», а «`0` — комментируется только самый свежий пост окна».
4. `npm test` — contract-тест скажет, если что-то забыто.
5. Обновить строку модуля в [MCP-MAP.md](./MCP-MAP.md) (счётчик параметров, дата).

Формат целиком — [MCP-SPEC.md](./MCP-SPEC.md). Живой пример на 32 параметра —
раздел «Нейрокомментинг» в [MCP-MAP.md](./MCP-MAP.md).

## Что произойдёт, если забыть

`server/__tests__/mcpDescriptors.test.js` падает: он сверяет поля, которые реально читают
воркер и валидатор, со списком в дескрипторе. Красный тест = PR не мержится. Это сделано
намеренно: дисциплина без проверки не работает, а мы уже один раз на этом встали.

## Новый модуль

Новый модуль = новый файл дескриптора. Пингани — сделаем вместе за один заход, там
15 минут: `whoAmI`, блоки, параметры, пресеты, пример запуска.

## Чего делать не надо

- Не описывай модуль в README/комментариях «чтобы было» — описание живёт **только** в
  дескрипторе, иначе снова появятся два расходящихся источника правды.
- Не дублируй ограничения в UI руками. Пришёл диапазон из дескриптора — бери его оттуда.
- Не выноси в MCP поисковые и чисто визуальные поля.
