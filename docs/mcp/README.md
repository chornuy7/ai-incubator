# MCP — карта раздела

> **Владение: MCP целиком наш (Илья / Lane A).** Напарник (Николай) MCP **не делает** —
> но обязан регистрировать в нём каждое новое поле и каждый новый модуль
> (правило и процедура — [MCP-CONTRIBUTING.md](./MCP-CONTRIBUTING.md)).
> Причина: MCP перестаёт быть «ещё одним эндпоинтом» — из него вырастает
> **отдельный сервис**, и схема должна иметь одного хозяина.

Раздел ведётся тщательно и постоянно: если параметр появился в коде, но его нет здесь —
это баг, а не «мелочь». Именно рассинхрон схемы и реальности заблокировал заказчика
на созвоне 14.08 («ни хрена не соотносятся то, что написано в джейсоне, с тем, какие
параметры реально есть у каждого модуля»).

## Живая документация — `/docs/mcp`

Одна страница, которая всё, что показывает, читает у самого сервера: список инструментов,
схемы входа и выхода, дескрипторы модулей, ресурсы, промпты, версии протокола и
возможности. Устареть ей нечем — она не хранит ни одного факта о протоколе.

У каждого блока есть **Run**: видно не только описание запроса, но и настоящий ответ
этого сервера, вместе с заголовками транспорта, которые тоже часть контракта.

```bash
npm run dev        # docs на http://localhost:3001/docs/mcp (рабочие данные)
npm run mcp:docs   # только docs, свой порт 3011 и ИЗОЛИРОВАННЫЕ данные
```

`npm run mcp:docs` нужен, когда основной дев-сервер уже занят: поднимать второй экземпляр
на тех же данных нельзя — при старте `reconcileStaleTasksOnBoot` помечает running-задачи
как `stopped`, то есть второй запуск глушит задачи первого. Схемы, инструменты и
дескрипторы живут в КОДЕ, поэтому в изолированном режиме они настоящие до последнего
поля; пустыми будут только аккаунты, задачи и пользователи.

Ключ — `MURMEX_API_KEY` из окружения сервера; страница держит его в `localStorage`
браузера и никуда, кроме этого сервера, не шлёт. Без ключа `/api/v1` закрыт целиком.
На проде (задан `SESSION_SECRET`) страница выключена, пока не задан `MCP_DOCS=1`.

> **Адрес — `/docs/mcp`.** Прежний `/mcp-docs` остался постоянным редиректом (301).
>
> Про адреса вообще: всё, что не `/api` и не зарегистрировано явно, перехватывает
> SPA-фолбэк и уводит на логин или в панель — так выглядит любая опечатка в пути, и так
> выглядела ссылка на несуществующую страницу, какое-то время стоявшая в документе
> метаданных RFC 9728. Теперь ссылка считается от живого маршрута (`MCP_DOCS_PATH`) и не
> отдаётся вовсе, если страница выключена.

Рядом лежит **политика использования данных** — [`/docs/mcp/policy`](../../server/mcp/docs/policy.html),
она же `resource_policy_uri` в метаданных RFC 9728: что эндпоинт отдаёт, что с этим можно
делать и какие обязательства возникают из того, что часть модулей пишет живым людям, которые
ни на что не соглашались. Доступна всегда, даже когда документация выключена.

Код — [`server/mcp/docs.js`](../../server/mcp/docs.js) +
[`server/mcp/docs/index.html`](../../server/mcp/docs/index.html) +
[`docs/policy.html`](../../server/mcp/docs/policy.html).

## Быстрый ответ на «что происходит»

**Было (до 14.08):** `GET /api/v1/mcp` — манифест-заглушка, 5 полей на модуль, без
ограничений и блоков. MCP только по названию: подключиться клиентом нельзя, и схема врала.

**Стало:** настоящий MCP-сервер — **`POST /api/v1/mcp`**, JSON-RPC 2.0 поверх Streamable HTTP,
`Authorization: Bearer <api-key>`. Десять инструментов (`list_capabilities`,
`describe_capability`, `list_modules`, `describe_module`, `describe_block`, `validate_task`,
`estimate_task`, `get_task`, `stop_task`, `create_task`), ресурсы `murmex://module/<key>` /
`murmex://help/<key>/<block>` и четыре рабочих промпта. Код — [`server/mcp/`](../../server/mcp/).

**Возможности спрашиваются срезами** (26.08): всё сразу · только модули · только
пользователь · одна конкретная возможность любого вида. Кроме модулей описаны
**подсистемы** — прокси, менеджер аккаунтов, дашборд задач, статистика и остальные, — и у
каждой посчитано, разрешена ли она владельцу ключа. [MCP-SPEC.md §8.8](./MCP-SPEC.md).

**Сейчас (26.08): протокол подтянут до ревизии `2026-07-28`, сервер двухэрный.**
Современные клиенты работают без рукопожатия (`server/discover`, per-request `_meta`,
`resultType`, коды −32020/−32021/−32022, `ttlMs`/`cacheScope`, пагинация); клиенты
`2025-11-25` и старше продолжают ходить через `initialize` — их не сломали. Подробности,
таблица соответствия спецификации и обнаружение авторизации (RFC 9728) — в
[MCP-SPEC.md §8](./MCP-SPEC.md).

Единственный источник правды — **дескриптор модуля** ([`server/mcp/descriptors/`](../../server/mcp/descriptors/)).
Из него собираются MCP-схема, валидация и help; поверх стоит contract-тест, который не даёт
схеме разойтись с кодом.
