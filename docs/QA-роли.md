## R1. После входа другим юзером шапка и «Мой аккаунт» показывают СТАРЫЙ (админский) профиль ✅
**Где:** правый верхний чип профиля (шапка) + страница «Мой аккаунт» (`/panel/user/profile`).
**Симптом (скрины):** вход выполнен как `ya.lonk777@gmail.com` — тост подтверждает

  это админский/старый профиль, а НЕ залогиненного Оператора.
**Надо:** шапка и «Мой аккаунт» должны отражать ТЕКУЩЕГО пользователя сессии
(Тестовый модератор / ya.lonk777@gmail.com), а не мок-профиль `data.user`.
**Вероятная причина:** AppHeader/ProfilePage читают `data.user` (мок), а не `useSession().user`.
**Приоритет:** высокий (иначе непонятно, под кем ты вошёл; путаница при тесте ролей).
**Статус:** ✅ ГОТОВО. AppHeader (чип + меню профиля) и ProfilePage теперь берут имя/e-mail из
`useSession().user` (fallback на мок при демо-режиме без сессии). «Выйти» в шапке чистит сессию

## R4. Менеджер аккаунтов: видно ЧУЖИЕ аккаунты без выданного доступа ✅
**Где:** «Менеджер аккаунтов» под не-админом.
**Симптом (слова заказчика + скрин):** пользователь видит все 5 аккаунтов, хотя они
«не его» и доступ на них не выдавался.
**Надо:** доступ к аккаунтам на УРОВНЕ аккаунта — пользователь видит только те аккаунты,
которые ему выданы (или которыми он владеет). Без выдачи — не показывать.
**Приоритет:** высокий (утечка видимости чужих аккаунтов).
**Статус:** ✅ ГОТОВО. Новый ресурс прав `resources.accounts` (accountId→allow/deny). В «Роли и
доступы» → «Ресурсы» блок «Аккаунты (кто виден роли)» со списком всех аккаунтов. Не-админ видит
в менеджере И в пикере (везде) ТОЛЬКО выданные аккаунты; по умолчанию (нет выдач) — пусто; админ
видит все. Каталог берёт аккаунты из метаданных (без подключения к Telegram). Проверено LIVE:
Оператор без выдач → 0 аккаунтов; выдали 2 → видит ровно 2 (Ілля, Claude Bet AI), остальные скрыты.
**Примечание:** гейтинг клиентский (как и для секций/модулей — единый паттерн); серверная
фильтрация /api/tg/accounts — отдельной задачей, если понадобится жёсткий бэкенд-энфорсмент.

## R6. Блоки внутри модуля НЕ гейтятся — видна вся страница, хотя выдан только 1 блок 🔧
**Где:** страницы модулей (замечено в Нейрокомментинге и Нейрочаттинге; касается всех модулей).
**Симптом (скрины):** роли «Оператор» выдан ТОЛЬКО блок «Запуск / остановка» (run), остальные
блоки — «Настройки и пресеты» (settings), «Целевые каналы/группы» (targets), «Шаблоны» (templates),
«Результаты» (results), «Логи» (logs) — сняты («Убрать»). НО при входе Оператором на странице
модуля видны ВСЕ секции: «Выбор аккаунтов», «Настройки чаттинга», «Защита аккаунтов», тайминги
и т.д. Должен показываться только блок «Запуск».
**Надо:** гейтить рендер секций модуля по правам `blocks` (`can('block', '<module>:<block>')`).
Каждую секцию (SectionCard) сопоставить с ключом блока (run/settings/targets/templates/results/
logs) и скрывать, если доступ не выдан. Определить минимум (напр. без «run» модуль бесполезен,
но роль может дать только «results»/«logs» для просмотра — тогда виден только просмотр).
**Причина:** права `blocks` в модели есть и сохраняются, но UI модулей (LiveModule /
NeuroChattingModule / NeuroCommentingModule / NeuroDialogs / ModuleRunner) рендерит все
секции без проверки `can('block', …)`. Enforcement блоков не сделан (в отличие от модулей/
разделов/аккаунтов).
**Приоритет:** высокий (иначе блочные права в матрице ничего не делают на странице).
**Статус:** 🔧 ЧАСТИЧНО. Сделано для модулей на базе **LiveModule** (нейрокомментинг,
нейрочаттинг, массовые реакции, масслукинг, прогрев, GGR): хелпер `showBlock(bk)` гейтит
секции по `can('block', '<модуль>:<блок>')`. Маппинг: run→Выбор аккаунтов+Запуск;
settings→Настройки/Тайминги/Защита; targets→Цели/Каналы/Ссылки/Чёрный список;
templates→AI-промпты/Эмодзи; results|logs→Результаты/История. Если не выдан ни один блок —
подсказка «обратитесь к админу». Проверено LIVE: Оператору дали только `run` для
нейрочаттинга → видны только «Выбор аккаунтов» и «Запуск», остальные секции скрыты.
**Осталось:** выделенные модули со своей вёрсткой — НейроДиалоги (NeuroDialogsModule),
парсеры (ChannelParserModule / ParticipantsParserModule), Мейлинг (MailingPage),
Автопостинг (AutopostingPage) — применить тот же `showBlock`. Follow-up.

**Вопрос по маппингу секций → блоки (уточнить при реализации):**
- «Выбор аккаунтов» — часть `run`? или отдельный минимум (если модуль доступен — виден всегда)?
- «Настройки чаттинга/комментирования», «Тайминги», «Защита» → `settings`;
- «Целевые каналы/цели», «Ссылки на посты» → `targets`;
- «Шаблоны сообщений/промпты» → `templates`;
- «Результаты/Визуал» → `results`; «Логи выполнения» → `logs`;
- «Запуск/LaunchPanel» → `run`.
