## 2. Supabase — перенос БД/auth/storage `[РЕШЕНО: Firebase vs Supabase → Supabase]`

Строки 72–132 + доуточнение в чате («база даних в base»).

- **Решение:** вся БД переезжает на **Supabase** (PostgreSQL). Причины из звонка:
  - управление юзерами и **временными/анонимными** юзерами из коробки (как в мобильных играх:
    зашёл → создался юзер, потом привязка к Google-аккаунту);
  - **OAuth 2.0** интеграции с любым сервисом из коробки;
  - **OTP** и **капча** из коробки (нужны на регистрацию/логин — вопрос безопасности);
  - **мейлинг**: mailbox + шаблоны писем (welcome / спасибо за авторизацию / забыли пароль …);
  - очень **гранулярный RLS** (row-level security) — управление доступом к таблицам/данным;
  - **авто-REST-API из таблиц** (не надо писать своё API), переносимо на свой сервер;
  - **Storage**: 5 ГБ free / от 10 ТБ на платном; бесплатный тариф щедрый (миллионы вызовов).
- **Как подключаем:** создать аккаунт на supabase.com → создать проект → подключить **Supabase MCP**
  к «ишке», залогиниться под аккаунтом, дальше AI сам выносит схему. Дать доступ через MCP + удалённое
  управление.
- **Оплатить сразу после запуска** — free-проект встаёт на паузу после **2 недель** неактивности;
  чтобы не легло — оплатить.
- **Где что хранить:** результаты парсера / найденные аккаунты → в Supabase. **Текстовые** данные →
  таблицы; **Storage** (bucket) — только файлы (картинки/видео/аудио).
- Связь с существующим: сейчас данные модулей — JSON в `server/data/` (см. ROADMAP Часть II).
  Это заменяется Supabase. **[❓]** стратегия миграции существующих JSON-стора.

  этого быть не должно. *Цитата:* «внутри самого кода этого вообще быть не должно».

## 6. Лендинг — переделка `[NEW, крупный блок]`

  разрастись в телеге»). Переключаемо, чтобы можно было менять подачу.
- **Два варианта лендинга**: (а) как **«инкубатор/комбайн»** (all-in-one) и (б) как **маркетинговый
  сервис через соцсети**. Переключение по **GET-параметру** в URL → меняет отображение, помогает
  **SEO/индексации**, даёт разные маркетинговые кампании.
- **Позиционирование — автоматический КОНВЕЙЕР / маркетинговый сервис**, а не «соберём базу каналов».
  Отличие от GramGPT/ручных комбайнов — **ставишь цель → всё работает автоматически** («настроил,
  забыл, работает за тебя»). Об автоматизации говорить везде.
- **Одно слово вместо трёх.** В первых 500 px три слова про одно и то же: *инкубатор / комбайн /
  конвейер*. Выбрать **одно** и использовать везде. Предпочтение заказчика — 3 отдельных лендинга (по
  GET-параметру), в каждом своё слово везде.
- **Не про внутрянку.** Не рассказывать про «прогрев/разогрев» — говорить, что продукт даёт
  **пользователю** (купить много аккаунтов, задать цель под рекламу группы/бота, перетягивание
  пользователей…).
- **«Подробнее» у модулей** сейчас ничего не делает — реализовать.
- **Готовые наборы** (по вовлечению / общению / outreach) — продавать как результат, а не список
