## 1. Авторизация / сессии / регистрация

**MR-141 (High) — Тайм-аут сессии + локальная проверка cookies.**
- Авторизованная сессия закрывается через **2-3 ч без активности** (без запросов в БД) → выкид на логин.
- Локальный скрипт каждые **~15 с** проверяет статус куки; умерла → выкид на логин; и в панели, и в админке. Делать **локально**, не с бэкенда.
- При смене аккаунта с админского на не-админский — выкинуть из админки.

**MR-142 (High) — Баги авторизации.**
- После входа с новыми кредами тянутся **старые данные прошлой БД** — чистить кэш/память приложения.
- Авторизация панели и админки **«шарятся»** — должны быть две разные.
- На форме регистрации **автозаполняются** email/пароль из кук.

**MR-143 (Medium) — Регистрация: валидация имени + баг баланса.**
- Текст ошибки валидации имени (только буквы/пробел/дефис/апостроф) — сделать понятным.
- Баг: при реге сразу поп-ап «баланс на нуле» + аккаунты не привязываются к учётке (область Николай).

## 2. Дашборд задач

**MR-144 (High) — Лимит параллельных задач в панели владельца.** Сейчас 3+1. Настройка — в панели владельца (не в админке); значение показывать на дашборде.

**MR-145 (Highest) — Задача с ошибкой: статус + карточка двойной высоты.** «Прям проблема».
- Провалившиеся задачи → статус **«ошибка»**.
- Карточка с ошибкой — **двойной высоты**: верхняя половина без изменений, нижняя = описание ошибки со скроллом.
- Ошибка видна в карточке (не только в тосте — он закрывается за 3-5 с). *(Экстра)* тоггл/кнопка «Ошибки» над Stop.

**MR-146 (High) — Warning-система задач.**
- Перед запуском проверять аккаунты (есть/рабочие/активные/не заблокированы).
- При загрузке дашборда анализировать аккаунты каждой задачи; отвалился, пока задача стояла → **warning** в карточке (второй блок, «2 из 10 с проблемой»).
- Градация по модулям: прогрев = warning, нейродиалог = ошибка.
- В «Аккаунты в работе»: статус+имя, фильтр активные/неактивные/проблема, «!» у проблемного; отключение аккаунтов от задачи в карточке.

**MR-147 (High) — Карточка задачи: вкладки + чистка + сортировка.**
- Вкладки **«Описание»** и **«Настройки»** (редактирование как при создании, переиспользовать блок «Выбор аккаунтов»).
- Убрать плашки Компании/Цели/Аккаунты/Каналы/Результаты; «Потрачено» и «Модуль» → к прогрессу; created/updated мелкими серыми.
- Сортировка (и все фильтры статусов): выполняется→в очереди→остановлено→ошибка→готово, разные цвета.

**MR-148 (Medium) — Редактирование/перезапуск + баги.**
- Завершённые задачи можно перезапускать/редактировать; «под MCP» — нельзя (сообщать).

## 3. Экономика / цены / токены

**MR-149 (High) — Оплата действия по максимуму + калькулятор.**
- Объединить оплату «отправка + генерация текста» в **одну цену за действие**.
- Цена по **максимуму символов** (лимит ТГ ~5000 / 1024 с картинкой); чарджим за максимум; себестоимость = токены×цена + наценка.
- Мини-калькулятор в шапке модуля (перед «Выбор аккаунтов»): цена за действие + «1 действие = N символов».
- Упростить нижнюю панель запуска: только «время» и «цена» двумя плашками.

**MR-150 (Medium) — Округление CEIL + токены подписки.**
- Округление цен CEIL до целых; фикс бага скидки (−35% вместо −20%).
- Подписка: общее число токенов/мес + «в подарок 200» отдельной жёлтой строкой; дефолт токенов на модуль (по умолч. 100).
- Цены на токены — в админку из БД; для клиента считать в «действиях».
