# CLAUDE.md — гид по проекту Myrmex

AI-платформа массового управления Telegram-профилями: прогрев, нейрокомментинг, нейрочатинг,
парсинг каналов, автоматизации, логи, аналитика. Фронт — React/Vite (`src/`), бэкенд —
Node/Express (`server/`), сессии Telegram через GramJS.

**Что лежит в этом файле:** только то, что должно действовать ВСЕГДА — запреты и карта. Процедуры
вынесены в скиллы (`.claude/skills/`) и подгружаются, когда нужны. Принцип деления:

> **Запреты — здесь. Инструкции — в скиллах.**

Запрет обязан сработать, даже если Claude не понял, в какой ситуации находится. Инструкция нужна
только внутри шага, который он уже начал.

## 🔒 Гейт — пять запретов, действуют всегда

Полная цепочка задачи, статусы, шаблоны и порядок шагов — скилл **`task-workflow`**.

```
Jira → задача (ссылка · поиск · завести) → npm run sync → своя ветка → работа
   → «тестируй» → Ai Testing → Human Testing → Done → «залей и смержи» → заливка + мерж
```

**1. Нет Jira — работы нет.** Допуск к заливке это статус задачи, и Claude смотрит его в Jira
**сам**, а не спрашивает у человека. Без подключения гейт `Done` непроверяем и превращается в
честное слово. Проверка делается ПЕРВЫМ действием.

**2. Нет ссылки на задачу — работы нет.** Но останавливаться молча нельзя: Claude обязан
**сначала поискать задачу в Jira** (`searchJiraIssuesUsingJql`) по сути проблемы и показать
найденное — вполне возможно, она уже заведена. Не нашлось или не подошло — **предложить завести
и показать черновик**. Порядок: ссылка от человека → выбор из найденного → создание по команде.

**Создать задачу можно только по явному согласию.** Постановка остаётся решением человека; Claude
делает механическую часть, а не решает, что делается. Молчание согласием не считается. Пока
задачи нет — работа не начата.

При нарушениях 1 и 2 разрешены ровно две вещи, и обе не являются работой над задачей: разбираться
с самим подключением и отвечать на вопросы по существующему коду, **ничего не меняя**. Всё, что
пишет в файлы, коммитит, заливает или мержит, — заблокировано.

**3. В `main` не коммитим никогда** — ни «мелочь», ни «только документацию». Ветка заводится до
первой правки и называется **`feat/<TaskID>-<TaskTitle>`**: ключ задачи как в Jira, затем краткое
название латиницей строчными через дефис — `feat/MR-212-claude-md`, `feat/MR-217-account-status`.
Кто автор, видно из коммитов, в имени ветки это не дублируется. Обнаружил, что работаешь в
`main`, — остановись и перенеси изменения в ветку.

**4. Пока задача не в `Done` — наружу не уходит ничего.** Ни `git push` в удалённую ветку, ни
деплой, ни мерж в `main`. `Done` ставит **только человек, вручную**, после `Human Testing`.
`Ai Testing` и `Human Testing` допуском НЕ являются.

**5. `Done` — не команда.** Увидев `Done`, Claude НЕ начинает заливку. Действие открывает только
прямое распоряжение словами: «залей», «мержи», «выкатывай». Молчание, «готово» и «ок» командой не
считаются. Разрешение на заливку не является разрешением на мерж — это два отдельных вопроса.

**Одной строкой: пока задача не в `Done` — не заливать и не мержить, даже если попросили; в
`Done` — не начинать, пока не прозвучала команда. На попытку — предупредить и остановиться.**

### Два шаблона, которые срабатывают до начала задачи

Остальные шаблоны — в скилле `task-workflow`: они звучат внутри задачи, когда скилл уже загружен.
Эти два срабатывают на первом же сообщении, когда никакого контекста ещё нет, поэтому лежат здесь.

Воспроизводятся **дословно** — слово в слово, включая регистр и знаки: шаблон должен узнаваться с
одного взгляда, пересказ это ломает.

Jira не подключена:

> **⛔ СТОП: JIRA НЕ ПОДКЛЮЧЕНА — РАБОТА ЗАБЛОКИРОВАНА.**
> **БЕЗ ДОСТУПА К СТАТУСУ ЗАДАЧИ ГЕЙТ `DONE` НЕПРОВЕРЯЕМ.**
> Что дальше: подключить коннектор Atlassian (настройки claude.ai либо `/mcp` в интерактивной
> сессии) и повторить запрос. До этого я не начинаю задачу.

Ссылки на задачу нет:

> **⛔ СТОП: НЕТ ССЫЛКИ НА ЗАДАЧУ — РАБОТА НЕ НАЧАТА.**
> **ИСКАЛ В JIRA ПО ЗАПРОСУ `<что искал>` — `<нашлось N подходящих / ничего не нашлось>`.**
> Что дальше, на выбор: пришлите ссылку · возьмём одну из найденных выше · скажите «заводи»,
> и я создам задачу по черновику ниже и покажу ключ.
> Без задачи нечему двигаться по статусам и нечем подтверждать допуск.

Читаемый пересказ регламента для человека — [docs/WORKFLOW-rules.html](./docs/WORKFLOW-rules.html)
(открывается двойным кликом, без сборки). **Шаблоны и формат ветки в нём генерируются отсюда**
(`npm run gen:workflow`), расхождение ловит тест `workflowDocsSync` — руками их править
бесполезно, перезапишется.

## Карта проекта

| Где | Что |
|---|---|
| `src/pages/`, `src/widgets/`, `src/features/` | экраны панели, снизу вверх по слоям |
| `src/shared/`, `src/api/` | общие компоненты и клиент API |
| `server/*.js` | роуты и доменные модули (`accountHealth`, `campaigns`, `channels`…) |
| `server/lib/` | ядро: `channelLease`, `accountLocks`, `accountRunner`, `actionBilling` |
| `server/modules/` | система модулей задач — три файла: `registry`, `routes`, `workers` |
| `server/mcp/` | MCP-сервер и дескрипторы → скилл `mcp-descriptors` |
| `server/data/` | локальный фолбэк хранилища (в `.gitignore`), не источник истины — см. ниже |
| `supabase/` | `schema.sql` и ~50 миграций — вторая половина хранилища |
| `server/__tests__/` | ~140 тестов, перечислены поимённо в `package.json` |
| `api-tests/` | **второй набор тестов**: Python, приватный `/api/v1` (ключ «мозгов»). `npm test` его НЕ запускает |
| `scripts/` | `sync.mjs`, миграции, генераторы, `mcp-docs.mjs` |
| `deploy/` | `deploy.sh`, nginx-конфиг, systemd-юнит — то, что запрещает трогать запрет 4 |
| `docs/CONTRACT-*.md` | контракты: state machine, lease, RBAC, логи действий и аудита |

**Хранилище одно, бэкенда два.** Общая база (Postgres/Supabase) — единственное место данных;
файлы в `server/data/` — фолбэк для локального запуска и тестов, включается отсутствием
`DATA_BACKEND=supabase` ([server/lib/supabase.js](server/lib/supabase.js)). Каталог в
`.gitignore`, в репозиторий не входит.

**Правило владельца (созвон 24.08, аудит MR-186):** другого способа хранения быть не должно —
ни файлов, ни `localStorage`, ни памяти процесса. Заводишь новый стор — сразу с веткой базы.
Что уже перенесено и что осталось — [docs/AUDIT-storage-2026-08-27.md](./docs/AUDIT-storage-2026-08-27.md).

## Документация

- **[ROADMAP.md](./ROADMAP.md)** — живой план по фазам и текущий статус. Выполнил пункт —
  **обнови его статус (`☐→◐→☑`) тем же PR.**
- **[docs/SUMMARY.md](./docs/SUMMARY.md)** — оглавление всей документации.

ТЗ в `docs/` — это протоколы созвонов, по одному на дату (`TZ-2026-07-10` … `TZ-2026-08-27`).
**Ни один из них не является источником истины для всего проекта**: каждый описывает решения
своего созвона, и по конкретному вопросу верен самый свежий документ, который его касается.
Отчёты (`REPORT-*`, `QA-*`) — срезы на дату, а не текущее состояние. Что действительно
поддерживается — `ROADMAP.md`.

## MCP — два правила, остальное в скилле

MCP — внешний контракт с «мозгами» заказчика, у схемы один хозяин. Подробности, исключения и
разбор витринных подписей — скилл **`mcp-descriptors`**.

1. **Добавил или изменил поле, сохраняемое в `task.settings`** (или завёл модуль) — внеси его в
   дескриптор **тем же коммитом**. Contract-тест `server/__tests__/mcpDescriptors.test.js`
   сверяет схему с тем, что читает воркер; рассинхрон = красный тест = PR не мержится.
2. **Язык MCP — только английский.** Всё, что уезжает клиенту протокола. Комментарии в коде и
   `docs/mcp/*.md` остаются русскими. Кириллица в полях наружу = красный тест.

## Навигация по коду — обязательна

Код ищется, читается и правится **инструментами, а не грепом**: Serena (символы TypeScript),
codebase-memory-mcp (граф кода, 158 языков), ast-grep (поиск по форме). Все три локальные.

> **Обязанность: прежде чем искать, читать незнакомое место, править, рефакторить или
> индексировать код — загрузи скилл `code-navigation`.** В нём разделение зон между
> инструментами; без него они дублируют друг друга, а поиск скатывается к грепу.

Установка обязательна для всех и держится не на просьбе: `npm run sync` — первый шаг любой
задачи — падает, если хоть одного инструмента нет.

## Запуск и проверка

`npm test` и `npx tsc --noEmit` — обязательны перед сдачей, результат сообщается **числом**.
`npm run dev` — фронт `:5173` + API `:3001`, **только через harness preview**, не фоновым bash.
**После правок воркеров и схем бэкенд надо перезапускать** — они живут в памяти процесса.

Порты, `useLiveApi`, миграции, ловушка с поимённым списком тестов — скилл **`verify-changes`**.

## Память

Две памяти, и они не смешиваются:

- **Файловая память Claude** — решения, договорённости и то, чего нет в коде и в истории git.
  Лежит **вне репозитория**, в профиле пользователя
  (`~/.claude/projects/<проект>/memory/`), поэтому у каждого своя и в PR не видна.
- **Заметки Serena** (`.serena/memories/`) — про код и устройство проекта, **в репозитории**,
  общие для команды, ревьюятся как обычный markdown. Корень графа — `core`.
