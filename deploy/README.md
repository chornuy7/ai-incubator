# Выкат на прод

Два способа. Автоматический — основной, ручной остаётся как запасной.

| | Автодеплой | Ручной |
|---|---|---|
| Как запускается | push в `main` (или кнопка в Actions) | `bash deploy/deploy-archive.sh` |
| Проверки перед выкатом | типы, тесты, сборка — обязательно | никаких, катит что есть |
| Когда нужен | обычная работа | Actions недоступны, срочный откат, выкат не из `main` |

Сервер: `45.142.142.216`, каталог `/opt/ai-incubator`, служба `ai-incubator` (systemd).
Прод — **не** git-репозиторий, поэтому код всегда приезжает снаружи: rsync-ом из
Actions или архивом из ручного скрипта.

## Настройка автодеплоя (один раз)

Автодеплой описан в [`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml) и
работает после того, как заданы три секрета. Пока их нет — workflow падает на первом же
шаге с понятной ошибкой, а не «выкатывает в никуда».

**1. Сделать пару ключей** (на своей машине; приватный ключ никуда не коммитить):

```bash
ssh-keygen -t ed25519 -f deploy_key -N ""
```

**2. Публичную половину — на сервер:**

```bash
cat deploy_key.pub | ssh root@45.142.142.216 'cat >> ~/.ssh/authorized_keys'
```

**3. Приватную — в секреты репозитория.** GitHub → репозиторий → Settings → Secrets and
variables → Actions → New repository secret:

| Секрет | Значение |
|---|---|
| `DEPLOY_SSH_KEY` | содержимое файла `deploy_key` целиком, вместе со строками `-----BEGIN…` и `-----END…` |
| `DEPLOY_HOST` | `45.142.142.216` |
| `DEPLOY_USER` | `root` |

Секреты добавляет человек — они не должны проходить через чужие руки, в том числе через
ассистента. После этого локальный файл `deploy_key` можно удалить: он больше не нужен,
а лежать без дела ключу от прода незачем.

**4. Проверить.** Actions → deploy → Run workflow. Прогон покажет каждый шаг; на
«Проверка здоровья» должен появиться ответ `{"ok":true,...}` и `✅ Выкат завершён`.

## Что делает автодеплой

1. Прогоняет типы, тесты и сборку. **Красное — выката нет.** Прод не место для проверки
   гипотез: до 21.08 этот workflow катил любой push, а CI бежал отдельно и ни на что не
   влиял, поэтому сломанный коммит спокойно уезжал на сервер.
2. Делает бэкап `server/data` в `/var/backups/ai-incubator/data-<дата>` и хранит
   последние 20 копий. Там живые сессии Telegram, аккаунты, цели и кампании — это самое
   ценное, что есть на сервере.
3. Заливает код rsync-ом с `--delete`. Удаление важно: файл, стёртый из репозитория, но
   оставшийся на сервере, ломает сборку мёртвым импортом (так упал выкат 14.08).
   `server/data` и `.env` исключены — это состояние и секреты прода.
4. Ставит прод-зависимости, записывает выкаченный коммит в `.deployed-sha`, перезапускает
   службу.
5. Ждёт `/api/health` до 40 секунд. Старт занимает около десяти: поднимаются планировщики
   и пересчитывается кэш trust. Если API не ответил — шаг падает и печатает последние 40
   строк журнала службы.

Два выката одновременно не пойдут: они выстраиваются в очередь и **не отменяют** друг
друга. Отменённый на середине rsync оставил бы сервер с половиной файлов.

## Что автодеплой НЕ делает

- **Не откатывается сам.** Если health не поднялся, прод остаётся со свежим кодом и
  лежащей службой. Откат — руками: `ssh root@45.142.142.216`, вернуть данные из
  `/var/backups/ai-incubator/`, выкатить прошлый коммит ручным скриптом
  (`REF=<sha> bash deploy/deploy-archive.sh`).
- **Не мигрирует базу.** Миграции Supabase применяются отдельно и осознанно.
- **Не спрашивает подтверждения.** Любой push в `main` уезжает на прод. Если это неудобно
  (например, напарник мержит свою ветку в `main` посреди дня), триггер стоит сменить на
  `workflow_dispatch` — тогда выкат будет только по кнопке.

## Ручной выкат

```bash
bash deploy/deploy-archive.sh
```

Возит `git archive` от `HEAD` (можно задать `REF=<ветка-или-sha>`), чистит файлы,
удалённые из репозитория, собирает на сервере и перезапускает службу. Проверок не
делает — прогоняйте `npm test` сами.
