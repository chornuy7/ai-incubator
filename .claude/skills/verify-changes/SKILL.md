# Запуск и проверка

## Прогон перед сдачей

```bash
npm test
```

```bash
npx tsc --noEmit
```

Оба обязательны перед переводом задачи в `Ai Testing`. **Результат сообщается числом** —
«столько-то из стольких-то», а не словом «прошло». Падает — назвать, что именно.

`npm run build` делает `tsc --noEmit && vite build`, то есть включает проверку типов. `npm run
lint` — это тот же `tsc --noEmit`, отдельного линтера в проекте нет.

### Тесты перечислены поимённо

`npm test` — это не глоб, а **явный список ~140 файлов** в `package.json`. Завёл новый
`server/__tests__/*.test.js` — **допиши его в список тем же коммитом**, иначе он молча не будет
запускаться никогда, и красный тест никто не увидит.

Проверить, что список полон:

```bash
node -e "const p=require('./package.json'),fs=require('fs');const l=new Set(p.scripts.test.match(/server\/__tests__\/[\w.-]+\.test\.js/g)||[]);const m=fs.readdirSync('server/__tests__').filter(f=>f.endsWith('.test.js')).map(f=>'server/__tests__/'+f).filter(f=>!l.has(f));console.log(m.length?'НЕ ЗАПУСКАЮТСЯ:\n'+m.join('\n'):'список полон')"
```

## Запуск

| Команда | Что поднимает |
|---|---|
| `npm run dev` | фронт `:5173` + API `:3001` вместе |
| `npm run dev:safe` | то же, но API через `scripts/dev-api-safe.mjs` |
| `npm run dev:web` | только Vite |
| `npm run dev:api` | только `node server/index.js` |
| `npm run mcp:docs` | живая документация MCP |

**Дев-сервер поднимается только через harness preview, не через фоновый bash.** Иначе процесс
остаётся висеть, порт занят, а следующий запуск падает по непонятной причине.

Проверка UI: `preview_start` → `read_page` / `read_console_messages` → скриншот. Руками человека
не проверяем и не просим — сначала смотрим сами.

## Откуда панель берёт данные

Файл `api.config.json` в корне, поле **`useLiveApi`**:

- `true` — запросы `/api` уходят на **боевой** сервер;
- `false` — на локальный `node server/index.js`.

Меняется одно поле, Vite перезапустится сам (`vite.config.ts` читает конфиг на старте). Настройка
**только для разработки**: собранная панель всегда ходит на свой домен.

Файл в `.gitignore` — намеренно: случайно закоммиченный `"useLiveApi": true` увёл бы чужой дев на
боевой сервер. Образец — `api.config.example.json`.

**Тест не сходится с ожиданием — сначала проверь этот флаг.** Половина «странных» расхождений
объясняется тем, что панель смотрела на бой, а не на локальный сервер.

## Перезапуск бэкенда обязателен

**После правок воркеров и схем бэкенд надо перезапускать** — воркеры живут в памяти процесса.
Без рестарта правка просто не применится, и будет видно старое поведение.

**Активные задачи рестарт переживают.** `reconcileStaleTasksOnBoot()`
(`server/lib/accountLocks.js`) переводит прерванные `running`/`queued` задачи в **паузу** с
пометкой `resumeOnBoot`, а `resumeMarkedTasks()` (`server/lib/taskRecovery.js`) поднимает их
сразу после согласования локов. Прогресс, `actionKeys` и курсоры лежат на диске, локи
перезахватываются штатным «Возобновить».

Поэтому после рестарта задачи, которые были в работе, **снова окажутся запущенными** — это
норма, а не двойной запуск. Задачи, остановленные человеком, не поднимаются: флаг ставится
только тем, кого прервал процесс.

> Раньше такие задачи помечались `stopped`, и каждый деплой убивал всю активную работу.
> Если встретишь это утверждение в старых отчётах — оно устарело.

## Правил коснулся — перегенерируй пересказ

`docs/WORKFLOW-rules.html` — версия регламента для человека. Шаблоны остановки и формат имени
ветки в нём **генерируются** из `CLAUDE.md` и скилла `task-workflow`:

```
npm run gen:workflow
```

Расхождение ловит `server/__tests__/workflowDocsSync.test.js` — он же подскажет команду. Правки
руками внутри блоков `<!-- GEN:… -->` бесполезны: перезапишутся. Всё остальное в файле —
оформление и объяснения — пишется руками и генератором не трогается.

Причина такого устройства: пока файл поддерживался вручную, он отставал от правил снова и снова,
в том числе сразу после проверки «всё синхронизировано».

## Миграции

```bash
npm run migrate
```

Запускает `server/scripts/migrate.mjs`. Появилась новая переменная окружения или шаг миграции —
это обязательно попадает в комментарий при переводе задачи в `Human Testing` (скилл
`task-workflow`, раздел «что понадобится для выката»).
