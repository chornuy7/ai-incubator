# Терминология с привязкой к коду

Термин без адреса бесполезен — по нему нельзя проверить, правильно ли названа сущность. Поэтому
каждое слово здесь привязано к тому, где оно живёт.

## Профиль ≠ Аккаунт

Самая дорогая пара в проекте. Это **разные сущности** с разными хранилищами, правами и лимитами.

| | **Профиль** | **Аккаунт** |
|---|---|---|
| Что это | человек, пользователь панели | управляемый бот, Telegram-сессия |
| Хранилище | `server/data/users.json` | `server/data/accounts-meta.json` |
| Роут | `/api/me`, `/api/admin/users` | `/api/accounts` |
| Права | `server/data/roles.json`, RBAC | лимитов роли не имеет, есть статусы и lease |
| Клиент | `src/api/` — пользовательские вызовы | `src/api/accountsApi.ts`, типы `Account*` |
| Сколько | один на человека | десятки и сотни на профиль |

**Как применять:**

- Заводишь поле про человека — оно `user*`/`owner*`, ложится к `users.json`.
- Заводишь поле про бота — оно `account*`, ложится к `accounts-meta.json`.
- В тексте интерфейса: «у профиля 40 аккаунтов», никогда не наоборот.
- В обсуждении лимитов всегда уточняй, чьих: лимит профиля (сколько ботов он может держать) и
  лимит аккаунта (сколько действий в сутки) — это разные числа.

**Почему это ловушка:** в предметной области Telegram «аккаунт» и «профиль» бытово синонимы.
Ошибка в этой паре уводит обсуждение требований в сторону ещё до того, как кто-то заметит
подмену, — и всплывает уже в реализации, когда права навешаны не на ту сущность.

## Логи, не «История»

| | |
|---|---|
| Пишем | **Логи** |
| Не пишем | История, Journal, Activity |
| Где | `src/pages/LogsPage.tsx`, `server/actionLog.js`, `server/data/audit.log.jsonl` |
| Контракты | `docs/CONTRACT-action-log.md`, `docs/CONTRACT-audit-log.md` |

**Живое нарушение, которое стоит починить:** `src/pages/ParsingHistoryPage.tsx` — «History» в
названии экрана парсера. Правило нарушено прямо в коде; при следующей правке этого экрана имя
приводится к `ParsingLogsPage`.

## Шаблоны поиска, не «Шаблоны»

Сохранённые наборы параметров парсера. Слово «шаблоны» в одиночку в проекте занято слишком
широко (шаблоны сообщений, промптов, пресеты модулей), поэтому уточнение обязательно.

Где: экраны парсера, пресеты модулей — `server/mcp/descriptors/` (`presets`).

## Где правило действует

Везде, где текст увидит человек или где имя закрепится надолго:

- подписи интерфейса, заголовки разделов, тексты ошибок и подсказок;
- **имена файлов, компонентов, полей, таблиц, роутов и типов** — код читают дольше, чем UI;
- документация в `docs/`, комментарии в Jira, сообщения коммитов.

## Где не действует

- **Пользовательские данные.** Человек назвал свою кампанию «История» — это его название, оно не
  переводится и не исправляется.
- **Внешние API.** `account_id` в ответе Telegram остаётся `account_id`, даже если по смыслу это
  наш аккаунт.
- **MCP.** Там своё правило — всё по-английски, скилл `mcp-descriptors`.

## Пополнение

Появилась новая путаница — её место здесь, вместе с адресом: хранилище, роут, экран. Термин без
привязки в эту таблицу не добавляется, иначе получается список слов, по которому ничего нельзя
проверить.
