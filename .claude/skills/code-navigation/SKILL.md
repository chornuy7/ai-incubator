# Навигация по коду

Репозиторий большой — около 500 файлов исходников плюс документация и миграции. Перебор грепом
по нему медленный и неточный: он находит совпадения строк, а не символы, и не отличает
определение от упоминания в комментарии.

**Правило: код ищется, читается и правится инструментами, а не грепом.** Грепу остаётся то, для
чего он и сделан, — найти строку или значение в конфиге.

Все три работают **только на этой машине** и в сеть не ходят: ни ключей, ни облачных сервисов,
ни эмбеддингов на стороне.

## Кто за что отвечает

Инструменты **не дублируют друг друга**. Правило разрешения спора в одну строку:

> Вопрос про **один символ в TS/JS** — Serena.
> Вопрос **шире одного файла** или **за пределами TypeScript** — codebase-memory.

| Вопрос | Чем | Инструмент |
|---|---|---|
| Где определён символ | Serena | `find_symbol` |
| Кто вызывает эту функцию | Serena | `find_referencing_symbols` |
| Что вообще есть в этом файле | Serena | `get_symbols_overview` |
| Правка внутри одного символа | Serena | `replace_symbol_body`, `insert_after_symbol` |
| Как устроен репозиторий, что с чем связано | codebase-memory | `get_architecture` |
| Как один модуль связан с другим | codebase-memory | `trace_path` |
| Поиск в SQL, миграциях, `.mjs`, документации | codebase-memory | `search_code` |
| Произвольный запрос к графу | codebase-memory | `query_graph`, `search_graph` |
| Что изменилось с прошлой сессии | codebase-memory | `detect_changes` |
| Шаблон кода по форме (`foo($$$)`, `await` без `try`) | ast-grep | `npx ast-grep run -p '…'` |
| Строка, текст, значение в конфиге | обычный grep | — |

### Почему именно так

**Serena** поднимает TypeScript language server. Он резолвит импорты, ре-экспорты и типы,
поэтому отвечает ссылками, а не совпадениями имён. На символе с частым именем это разница между
двумя ответами и шестьюдесятью кандидатами. Плата — он видит только TypeScript.

**codebase-memory-mcp** держит граф кода: на этом репозитории 7659 узлов и 28388 связей. Знает
158 языков, поэтому видит то, чего TS-сервер не видит вообще: SQL-миграции в `supabase/`,
`.mjs`-скрипты в `scripts/`, конфиги, документацию в `docs/`. Отвечает на вопросы про структуру,
а не про отдельный символ.

**ast-grep** ищет по форме кода, без индекса и без MCP — обычной командой через Bash. Нужен,
когда вопрос не «где этот символ», а «где такой шаблон».

## Как они разведены технически

Чтобы не мешали друг другу — четыре уровня, а не пожелание:

| | Serena | codebase-memory |
|---|---|---|
| Пространство имён | `mcp__serena__*` | `mcp__codebase-memory__*` |
| Каталог | `.serena/` | `.codebase-memory/` |
| Порт UI | 24282 | 9749 |
| Индексация | только TypeScript | `.cbmignore` запрещает `.serena/` и `.claude/` |

`.cbmignore` здесь не косметика: без него граф засосал бы 34 МБ кеша Serena.

## Установка обязательна для всех

`npm run sync` — первый шаг любой задачи — **падает с ошибкой, если хоть одного нет.**
Не установлено → задача не начинается. Проверка держится на скрипте, а не на просьбе.

- **codebase-memory-mcp** — в `devDependencies`, приезжает с `npm i`, отдельной установки нет.
- **ast-grep** — там же, тем же способом.
- **Serena** — один раз на машину:

```
uv tool install -p 3.13 serena-agent
serena init
```

Дальше ничего делать не нужно: `.mcp.json` лежит в репозитории и подхватывается сам.

## Проверка и обслуживание

```
serena project health-check .
npx codebase-memory-mcp cli index_status --repo-path .
```

UI: Serena — `http://localhost:24282/dashboard/`, граф — `http://localhost:9749`.
Оба слушают только `127.0.0.1`.

**Индекс графа обновляется сам** (`auto_watch: true`). Полная переиндексация нужна редко — после
крупного слияния, переезда каталогов или на новой машине:

```
npx codebase-memory-mcp cli index_repository --repo-path . --mode full
```

Занимает около минуты на этом репозитории (532 файла, ~7600 узлов).

**Каталог `.codebase-memory/` не коммитится, и флаг `--persistence` использовать не надо.** Он
пишет артефакт `graph.db.zst`, которым в теории можно поделиться с командой, — но `auto_watch`
перестраивает индекс на любую правку файла. Закоммиченный артефакт означал бы вечно грязное
дерево, а `npm run sync` на грязном дереве останавливается: первый шаг любой задачи оказался бы
заблокирован навсегда. Индекс дешевле собрать локально.

## Чего делать не надо

- **Не менять `token_count_estimator` в `~/.serena/serena_config.yml`.** По умолчанию там
  `CHAR_COUNT` — счёт по символам, локально. Вариант `ANTHROPIC_*` шлёт запросы в сеть.
- **Не коммитить `.serena/cache/` и `.codebase-memory/logs/`** — они в `.gitignore`, у каждого
  свои и большие.
- **Не начинать с грепа по всему репозиторию.** Если вопрос про символ или структуру — он
  адресован одному из инструментов выше.
