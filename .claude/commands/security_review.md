Проведи тщательный **security review** изменений текущей ветки (закоммиченных `main...HEAD` и незакоммиченных). `$ARGUMENTS` — опциональный фокус (путь/область); если задан — ограничься им, иначе смотри весь diff.

Начни с обзора объёма: `git status`, `git diff --stat main...HEAD`, затем читай затронутые файлы (не только diff — контекст вокруг тоже).

## Что проверить (стек: Node/Express ESM + GramJS + React/Vite)

1. **Секреты и ключи** — захардкоженные токены/пароли, `TELEGRAM_API_ID/HASH`, `OPENAI_API_KEY`, cookies TGStat; не утёк ли `.env`, `.session`, `server/data/` в git (должны быть в `.gitignore`).
2. **Аутентификация и доступы** — dev-bypass / fail-open ветки; отсутствие проверки владельца ресурса (IDOR); возможность назначить/«захватить» чужой аккаунт мимо локов (`accountLocks`) и статусов (`accountStatus`/`assertAccountsAssignable`).
3. **Инъекции** — command injection в `child_process`, `eval`/`Function`, path traversal при работе с файлами (`server/data`, пути сессий из пользовательского ввода).
4. **SSRF и внешние запросы** — TGStat-скрейпинг, пользовательские URL/прокси, инвайт-ссылки; куда и какие данные уходят наружу.
5. **XSS / небезопасный рендер (фронт)** — `dangerouslySetInnerHTML`, вставка непроверенного HTML/Markdown, `href` из данных.
6. **Десериализация/парсинг** — `JSON.parse` на недоверенном вводе, cheerio на внешнем HTML, регэкс-DoS.
7. **Логи и аудит** — не пишутся ли секреты в логи; критичные действия (перенос профиля, смена статуса, force-снятие лока) должны попадать в аудит (`auditLog`).
8. **Rate limit / DoS** — нет ли незащищённых дорогих роутов (login, парсинг, экспорт) без ограничений.
9. **Зависимости** — новые пакеты/версии с известными проблемами.

## Формат отчёта

Для каждой находки: **severity** (`critical`/`high`/`medium`/`low`), `файл:строка`, суть, **конкретный сценарий эксплуатации** (входные данные → последствие), рекомендация по фиксу. Сортируй от `critical` к `low`. Разделяй подтверждённые находки и предположения. Если серьёзного не нашёл — скажи прямо и перечисли, что проверил. Не выдумывай уязвимости ради объёма — только по фактам кода.
